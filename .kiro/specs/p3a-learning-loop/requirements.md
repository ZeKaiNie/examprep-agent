# P3a 学习闭环核心：需求

P3 拆为三段：**P3a 学习闭环核心（本 spec）**、P3b 服务（FastAPI + SSE + Alembic）、P3c Web App（需要 Node 20+）。
依据：`docs/design/04-agent-core.md` 第 1、2、4、7 节，`docs/design/05-pedagogy.md` 第 1、2、4、5 节，`docs/design/06-roadmap.md` P3 行。

## R1 学习记录
1. 选课记录（enrollment）：用户、课程、当前章、模式（cram / longterm）、起点（zero / weak / gap）、考试日期、档位（small / standard / large）。
2. 章节进度：每章已讲到第几段、总段数、状态（todo / teaching / covered / verified）、检查题连续答错次数。
3. 作答记录只追加：题号、作答原文、判定（right / wrong / partial / unsure / skip）、得分、判分来源（rule / llm / self）、错误类型、理由、是否用过提示。
4. 笔记：章节小结（summary）、困惑点（confusion）。
5. 本地用户固定为 `me`，所有表带 `tenant_id`。

## R2 分段与档位
1. 一章按证据块顺序切成“段”，每段约 N 字（small：中 1800 / 英 3000；standard：3000 / 5000；large：8000 / 12000）；同一份资料、同一档位切分结果稳定。
2. 档位按 tutor 模型的上下文长度自动选择（≤ 32k → small，≤ 200k → standard，否则 large），可手动指定。

## R3 意图识别与状态机
1. 规则分类用户输入：继续、考我、作答、要提示、看答案、跳到某章、看进度、没懂、本章结束、提问。等待作答时，非指令输入一律视为作答。
2. 状态：TEACH、CHECK、PRACTICE、FEEDBACK、WRAPUP、ASK；迁移由代码决定，模型只生成内容。
3. 策略矩阵（起点 × 剩余天数）决定：讲完每段是否 CHECK、每章练几题、是否启用提示阶梯。
4. CHECK：Tutor 讲完一段后提一个检查问题；学生回答由 Grader 判断是否理解；没懂则换讲法重讲，最多 2 次，之后记为困惑点并继续。
5. PRACTICE 选题：本章未解决的错题 → 未做过的真题 → 未做过的其他题 → 做过的题。
6. WRAPUP：Tutor 写 3–6 行小结存为笔记；本章有一道带参考答案的题答对过 → verified，否则 covered；进入下一章。
7. 每轮结束给出 2–3 个下一步建议。

## R4 引用由系统生成（反幻觉）
1. 每轮给 Tutor 的证据块编号为 E1…En，编号到 (文件, 页, 字符区间, 证据 id) 的映射只在服务端。
2. Tutor 只写 `[[E3]]`；渲染时替换为可点击的引用（文件 + 页码）；不存在的编号被删除并记录。流式输出时也能逐段替换。
3. 进入对话历史的助手消息去掉引用标记，避免旧编号干扰后续轮次。
4. Verifier 逐句校验带引用的句子：supported / partial / unsupported；unsupported 的句子标 🟡。

## R5 提问与拒答
1. 提问时检索本课程证据（优先当前章，再全课程）；没有命中直接回复“资料里没有讲到”，不调用模型。
2. 有命中时 Tutor 基于证据回答；证据不足时按规定回复“资料里没有讲到”（可另附标 🟡 的补充）。

## R6 判分
1. 先规则判分（P2 的 grade_answer）；结果不确定、且有参考答案时交给 Grader 子 Agent（只看题目、参考答案、学生答案）。
2. Grader 输出结构化结果：判定、得分 0–1、命中的要点、错误类型、理由。
3. 没有参考答案的题：Grader 可给出 🟡 参考判断，但不计入 verified。
4. Grader 失败或超时：展示参考答案，请学生自评。
5. 提示阶梯（策略开启时）：提示 1 指出知识点、提示 2 第一步、提示 3 关键中间结果，然后揭晓答案；用过提示的作答记录 `hints_used`。

## R7 会话与模型配置
1. 对话事件写入 P1 的事件存储（SQLite），重启后能接着学。
2. 模型配置：数据目录下 `config.toml`（providers、roles），或只设环境变量 `DEEPSEEK_API_KEY` 等自动选择默认模型。
3. 命令行 `examprep study <课程>`：交互式学习，流式显示讲解，显示引用、校验结果和下一步建议。

## 验收
- FakeProvider 驱动的确定性测试：在中文样例上完整走完一章（讲解 → 检查 → 练习 → 规则判分与 LLM 判分 → 小结 → verified），以及换章、看进度、提示阶梯、看答案。
- 引用：只会出现资料中真实存在的文件与页码；模型编造的编号被删除并计数；流式与非流式渲染结果一致。
- 拒答：资料外问题不调用 Tutor 直接拒答；证据不足时按格式拒答。
- 判分：规则可判的不调用 LLM；Grader 失败时降级为自评。
- 重启后进度与对话历史恢复。
- 覆盖率 ≥ 85%；ruff、pyright 零错误；CI 全绿。
