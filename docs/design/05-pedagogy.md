# 05 · 教学引擎：状态机、策略、学习者模型

Skill 里靠 SKILL.md 表格和 📍 行维持的教学流程，在这里变成代码。

## 1. 教学状态机

```
            ┌──────────── ASK（自由提问，任何状态都可进入，答完回到原状态）
            │
ONBOARD ──► PLAN ──► TEACH ──► CHECK ──► PRACTICE ──► FEEDBACK ─┐
   ▲                   ▲         │                      │        │
   │                   └─────────┘（没懂：换讲法重讲）    │        │
   │                   ┌─────────────────────────────────┘        │
   │                   ▼                                          │
   │                WRAPUP（写本章小结 → done/verified）◄─────────┘
   │                   │
   └── REVIEW（到期复习、错题回炉；新会话开始或调度器触发时优先进入）
```

| 状态 | 进入条件 | 做什么 | 退出 |
|---|---|---|---|
| ONBOARD | 新课程 | 导入资料、确认考试日期和模式、选起点（可选一个摸底小测） | 完成设置 |
| PLAN | 每天第一次进入、考试日期变化 | Planner 生成今日任务 | 用户确认或直接开始 |
| TEACH | 当前章还有未讲的段 | 讲一段（规则见第 4 节），带引用和图 | 讲完一段 |
| CHECK | 每段讲完后，按策略决定是否进入 | 问一个检查理解的小问题（来自本段内容，不计分） | 答对 → 下一段；答错 → 换讲法重讲，最多 2 次后记为困惑点 |
| PRACTICE | 一章讲完，或策略要求“讲完就练” | Examiner 选题 | 学生作答 |
| FEEDBACK | 有作答 | 判分 → 更新掌握度与复习卡 → 讲评 | 继续练或结束 |
| WRAPUP | 本章题目做完或用户说“这章好了” | Tutor 写 3–6 行小结存为笔记；答对过本章材料题标 `verified`，否则标 `covered` | 下一章 |
| REVIEW | 有到期卡片或待回炉的错题 | 按 FSRS 顺序出题 | 到期卡清空或用户跳过 |
| ASK | 用户自由提问 | 检索 → 回答或拒答 | 回到原状态 |

**意图识别**：用户的每句话先过一个轻量分类（规则优先，必要时用便宜模型）：继续 / 提问 / 作答 / 要提示 / 看答案 / 跳章 / 看进度 / 闲聊。分类结果决定状态迁移，Tutor 只负责生成内容。

**下一步建议**：每轮结束时，状态机给出 2–3 个快捷按钮（“继续”“考考我”“这里没懂”），替代 Skill 的 📍 行。用户不需要记命令。

## 2. 策略矩阵（复活 v4.3 的 3 × 4）

起点模式 × 剩余时间决定状态机的参数：

| | ≤ 1 天 | 1–3 天 | 3–7 天 | > 7 天 / 长期模式 |
|---|---|---|---|---|
| **零基础** | 只讲真题考到的知识点；不进 CHECK；每章 1 道真题 | 每章讲完练 2–3 题；CHECK 只在难点 | 每段 CHECK；每章练完再进下一章 | 按知识点依赖顺序；每段 CHECK；FSRS 复习 |
| **补弱** | 已掌握章节跳过，薄弱章节只讲要点 + 真题 | 已掌握章节每点 1 道难题验证 | 同左，加错题每日回炉 | 同左，FSRS 复习 |
| **查缺** | 直接 PRACTICE，错了才 TEACH | 每章先测后讲 | 同左 | 同左 |

具体参数：`teach_granularity`、`check_probability`、`questions_per_chapter`、`skip_mastered_threshold`、`hint_ladder`（是否先给提示再揭晓答案）、`review_daily`。

这些参数也是用户在设置页可以手动调整的。

## 3. 学习者模型

### 3.1 掌握度：BKT

每个知识点一组参数：初始掌握 P(L0)、学会概率 P(T)、失误 P(S)、猜中 P(G)。

- 默认参数按题型给：选择题 P(G)=0.25，判断题 0.5，其他 0.1。
- 每次作答（只有材料题和 CHECK 问题计入）更新后验。一道题关联多个知识点时，按标注权重分摊。
- 掌握概率 ≥ 0.85 且至少答对过一道材料题，才显示为“已掌握”。这延续了 Skill 的 `verified` 原则。
- 数据积累后可以按用户群体拟合参数，后期再考虑轻量 DKT。

### 3.2 复习：FSRS

- 卡片两类：**题目卡**（真题和作业题）、**知识点卡**（从资料生成的回忆问题，必须带证据引用，标 🟡 表示问题是 AI 改写的）。
- 判分结果映射到 FSRS 评分：答对且无提示 → Good；答对但用了提示 → Hard；答错 → Again；很快答对 → Easy。
- 突击模式下，考试日之后的复习时间没有意义：Planner 把考前到期的卡片按“掌握度低 × 真题频次高”压缩排到考前。

### 3.3 错因

- Grader 输出错误类型：概念错误、计算错误、审题错误、步骤缺失、记忆错误。
- 同一知识点的概念错误累积两次以上，生成一条 `Misconception`，进入 L3 快照，Tutor 讲相关内容时会提到。
- 学生说“这里没懂”时直接记为困惑点（沿用 Skill 的 `note --type confusion`）。

## 4. 讲一段内容的规则（来自 Skill §3，写进 L0 和教学策略）

1. 先用日常语言讲概念，假设学生第一次见。
2. 公式：先说每个符号的意思，再说为什么成立，最后走一个小例子。
3. 来自资料的内容带 `[[E]]` 引用；自己补充的标 🟡。
4. 例题完整走一遍，不总结。
5. 答案是结构（树、状态机、遍历顺序、数值表）的题，先逐步算，再画或列结果。
6. 有图先展示图，再讲图。
7. 结尾一句话连接上一个知识点，然后停下。

这些规则拆成 `skills/` 下的几份策略文件（讲公式、讲例题、讲图题、讲证明、提示阶梯），状态机按当前内容类型加载对应的一份，而不是每次全部塞进上下文。

## 5. 提示阶梯

长期模式默认开启，突击模式默认关闭（时间不够）。

1. 提示 1：指出该用哪个知识点（带引用）。
2. 提示 2：给出第一步。
3. 提示 3：给出关键中间结果。
4. 揭晓答案：展示参考答案和答案图，完整讲解。

每用一级提示，FSRS 评分降一档。

## 6. 计划器

- **突击模式**：剩余章节按“真题题数 × (1 − 掌握度)”排序后分配到考前天数，最后一天留给错题和小抄（沿用 Skill 的 `plan`）。时间不够时明确告诉学生哪些章节放弃。
- **长期模式**：知识点依赖图做拓扑排序，每天的新内容量受“今日到期复习量”约束（复习多时少学新内容）。
- 计划由代码算出，LLM 只负责把计划写成自然语言说明。

| 产出 | 来源 | 形式 |
