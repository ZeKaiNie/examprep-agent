## 真实模型验证（deepseek-flash，2026-11-12）

阈值调到 8000 token（默认 60000），让章内触发自动压缩；3 章 30 轮输入，最后手动压缩一次，再问“刚才那道先序后序的题，你举的例子是什么来着？”。跑了 2 轮（live7、live8，Key 只放环境变量）。

| 项 | 结果 |
|---|---|
| 触发 | live7：自动 1 次 + 手动 1 次；live8：自动 2 次 + 手动 1 次，全部成功 |
| 压缩幅度 | 约 8.5k → 0.6–0.7k token，每次 5–8 秒 |
| 压缩请求的缓存命中 | 90%、93%、95%（复用上一次讲解请求的前缀）；在只有 6 条消息的短段上手动压缩为 78% |
| 摘要是否属实 | 抽查摘要里提到的 12 个例子和数值（餐盘、快递、羽毛球筒、隧道、front = 4/rear = 1、BST 50、30、70 等），全部在压缩前的对话里出现过；做过的题、判定、注入被忽略都记对了 |
| 压缩后的连贯性 | 压缩后的章末小结引用正常（编造编号 0）；问“刚才举的例子”，两轮都答出了学生自己举的 A–B 左右孩子反例 |
| 其他质量 | 11 题判定与之前 6 轮完全一致；Grader 全部通过 `submit_result`；Tutor 首字延迟平均 0.84–0.93s |
| 缓存与花费 | 总体命中率 79–80%（不压缩时 80.7%，阈值调得这么低也几乎不降）；一次 3 章完整学习 $0.063–0.067 |

发现并修复的问题：

| 问题 | 原因 | 修复 |
|---|---|---|
| live7 摘要写了“学生说‘这里没懂’”“学生表示这章好了”，学生没说过 | 系统替学生补话：重讲时写“学生说：这里没懂”，小结时写“学生说：这章好了”，提示、讲评也有类似的补话；摘要把这些当成事实 | 只把学生这一轮的原话写进第一次 Tutor 调用，同一轮里系统接着做的动作不再冒充学生说话（新增测试） |
| 压缩后问“刚才的例子”，回答第一句是“资料里没有讲到这一点” | 提问指令要求资料不足时先写这句；问的是对话本身 | 提问指令写明：问对话里发生过的事时根据对话和摘要回答，不写这句（live8 已正确） |
| live8 有 2 次逐句核对 30 秒超时（其余 58 次最长 12 秒），核对被静默跳过 | DeepSeek 偶发慢请求 | 核对失败重试一次；仍失败时提示学生“这条讲解没能完成逐句核对”（新增测试） |

## 离线验收（2026-11-11）

488 个测试通过，总覆盖率 96%，ruff、pyright 零错误。

真实模型验证方法：`$env:COMPACT_MAX='8000'; $env:DEEPSEEK_API_KEY='...'; uv run python .tmp/p3a_live.py live7`，阈值调小让每章都能触发自动压缩，脚本最后还会手动压缩一次，并在压缩后问“刚才举的例子是什么”。
