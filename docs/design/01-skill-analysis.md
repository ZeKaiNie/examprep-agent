# 01 · Skill 拆解：继承什么、复活什么、丢掉什么

对象：`ZeKaiNie/universal-examprep-skill`，Flash v5.3 全部代码，加上 `full/`（v4.3）、`eval/`、`CHANGELOG`、`tests/`。
本文是新 Agent 设计的事实基础。

## 1. Flash v5.3 的真实结构

约 2500 行纯标准库 Python，管线是 `extract → chapters → questions → figures → guard → index → state → cli`。

| 模块 | 核心做法 | 关键参数/细节 |
|---|---|---|
| `extract.py` | PDF 用 pypdfium2/pypdf，DOCX/PPTX 直接解 zip+XML，TXT 依次尝试 utf-8-sig/gb18030/latin-1，HTML 用正则去标签 | 页文本少于 20 字记为空页；页首页尾 2 行内、重复出现在一半以上页面的短行视为页眉页脚；文件分类先看路径（solution > exam > homework > notes > lecture），再看正文开头 |
| `chapters.py` | 三条规则：文件名带编号即一章；无编号文件内出现至少 2 个递增的“第N章/Chapter N”就拆分；剩下的按文件顺序排在后面 | 递增比例要求 ≥ 60%；“Lecture N:” 标题行后最多拼 3 行当标题；图片文件按文件名里的数字挂到章 |
| `questions.py` | 四种题号风格（Problem N / 第N题 / `1.` / `(1)`），显式风格优先；`pair_key` 归一化文件名配对题目和解答；教材题号 `1.3.10` 精确匹配 | 节标题“二、填空题”重置编号；扫描页上不续接上一题；解答文件里去掉与题面重复的行；题型识别 choice/true_false/fill_blank/subjective |
| `questions.grade_answer` | 只判能机械比较的：选项字母集合、对错、单个数值（容差 max(半个末位, 1%)）、30 字内填空 | 文字填空只会判“对”或“不确定”，绝不判错 |
| `assign_chapters` | 题目显式章号 → 教材题号首段 → BM25 推测（标记 `chapter_guessed`） | |
| `figures.py` | 遍历 PDF 页对象（嵌套 Form XObject 做坐标变换），图片和路径对象框聚类（间隔 10pt），过滤小于 48×36pt 的，去掉在 40% 以上页面重复出现的装饰框，每页最多 4 张 | 图片覆盖页面 60% 以上判为扫描页；题目/答案区域只有和图形重叠才裁；自己写 PNG 编码器，不依赖 Pillow |
| `guard.py` | 输出材料一律包在 `<<<MATERIAL id … MATERIAL>>> id` 里，id 是内容 sha256 前 6 位；中英文 28 条注入正则；NFKC 归一化、去零宽字符，跨行拼接检测 | 32 条注入样例全部命中，20,363 行真实课件零误报 |
| `index.py` | 纯 Python BM25（k1=1.5, b=0.75），600 字一块，每次查询重建 | 中文按字二元组切分 |
| `state.py` | 单文件 `study_state.json`，原子写（tmp + replace），同时重新生成 `progress.md`、`notebook.md` | 存考试日期而不是天数（v5.3 修复） |
| `cli.py` | 17 个子命令；三档 profile（small 中文 1800 字一段/每次 1 题，standard 3000/3，large 8000/5）；每条输出末尾 📍 行写明下一条命令 | `plan`：剩余章节均分到考前天数，最后一天留给错题和小抄；章节过多时按真题出现次数挑重点 |

## 2. 演进中踩过的坑（新 Agent 必须记住）

1. **说明书过长，小模型就跑不动**。v4.3 开讲前要读约 140 KB 的技能文本，v5 压到 6.5 KB 才让 flash-lite 和 Haiku 跑通。结论：流程约束放进代码，给模型的指令要短。
2. **让模型自己做机械工作必然失败**。v4.3 要求模型渲染页面、拼总览图、写回执，弱模型一步都做不到；v5.1 改由脚本裁图后才可用。
3. **学生的手写作业被当成标准答案**（v4.3）。扫描页检测和 `student_attempt` 分类是硬需求。
4. **“讲过”不等于“会了”**。`verified`（答对过材料题）和 `covered_unverified` 必须分开。
5. **题干不在资料里时模型会编题**（v5.1 实测 flash-lite）。只能从参考答案开头复述已知条件，并标 🟡。
6. **模型忘记记录结果**。v5.3 用 `grade` 让脚本判客观题并直接记录。
7. **时间要用日期算**。存“3 天”几天后仍显示 3 天（v5.3）。
8. **注入防御要告知学生**。测试中模型忽略了注入但没告诉学生，后来规定必须说一句。
9. **并行学两门课会串工作区**（v5.2）。新 Agent 必须原生支持多课程、多会话隔离。
10. **安装包要小、要能审计**。skills.sh 安全扫描曾报 W008/W012，安装包从 12 MB 降到 150 KB。
11. **VS Code 类面板会拦截工作区外的图片**。新 Agent 有自己的 UI，这个问题自然消失。
12. **代码量膨胀到 14.4 万行，大部分在做回执和事务**（v4.3）。教训：用数据库事务解决一致性问题，不要用 JSON 文件模拟。

## 3. v4.3 里值得在 Agent 中复活的设计

| 设计 | v4.3 的样子 | 为什么当时失败 | Agent 里怎么做 |
|---|---|---|---|
| 3 模式 × 4 时间档 | 零基础 / 补弱 / 查缺 × ≤1天 / 1–3天 / 3–7天 / >7天 | 靠模型每轮记住长规则 | 变成教学状态机的策略参数，由代码决定每轮动作 |
| 知识点窗口 | `knowledge_window[]`，状态只有在窗口/窗口外/已验证，没有任何时间算法 | Skill 没有时钟和调度器 | 用 FSRS 做真实调度，后台定时推送到期复习 |
| 确定性难度分 | 跨知识点数、10 类结构族、是否需读图、答案跨页、章节位置、开放题型，0–8 分映射到 1–5 级 | 本身可用，只是 v5 删了 | 入库时计算，之后用作答数据校准 |
| 六种题型 | choice / subjective / diagram / fill_blank / true_false / code | v5 简化为 4 种 | 恢复 6 种，diagram 题“先算后画”，code 题可选沙箱运行 |
| keywords 判分 | 只有约定，没有代码 | 依赖模型自觉 | 判分子 Agent 输出结构化的要点覆盖结果，并留存依据 |
| 引文核验 | claim → 引文片段 → 来源单元，只证明“引文存在” | 全链路哈希太重 | 引用由系统生成（见 04 文档），再做蕴含校验 |
| 页面质量分流 | fast / recover / review，按乱码、公式、多栏等打分 | MinerU/Docling 只留了接口，从未启用 | 服务端真正接入：低质量页才走 OCR、VLM 或重型解析器 |
| 子 Agent 逐题精讲 | 每题一个干净上下文 | 宿主不一定支持 | 自己的运行时原生支持子 Agent |

## 4. 不复活的设计

代际账本、回执、哈希绑定、恢复日志、变更锁：全部由数据库事务、`material_version` 字段和任务队列替代。
`artifact_mode`、`interaction_style` 等开关：交给 UI 设置页，不进 prompt。

## 5. 新 Agent 的直接复用清单

可以基本原样移植（加类型标注、改成纯函数、接入数据库）：
`extract` 的各格式读取与页眉页脚去除、`chapters` 全部规则、`questions` 的切题与配对与 `grade_answer`、`figures` 的 PDF 图区检测和裁剪、`guard` 全部、`text` 的分词与分段、v4.3 的 `score_difficulty`。
现有 43 个测试用例和内置中文样例一起迁移，作为回归基线。
