# 04 · Agent 核心设计

本文讲项目里和大厂 Agent 面临同类问题的部分：循环、上下文、记忆、多 Agent、并发、持久化、反幻觉、安全、可观测性。
每节写明参考了谁、我们的做法、为什么这样做。

## 0. 总原则：确定性优先，模型兜底

Skill 的演进证明了一件事：能用代码做的事交给模型，模型就会出错。所以：

- **流程**（下一步讲什么、什么时候出题、什么时候复习）由教学状态机决定。
- **事实**（原文、页码、题目、答案、判分规则）由工具和数据库提供。
- **模型**负责三件事：用学生听得懂的话讲解、理解学生的自由提问、判主观题。

这样做的好处是小模型也能用：它只需要在很窄的范围里生成内容。

## 1. Agent 循环（`kaopu_agent.loop`）

参考：pi-agent-core 的事件流和钩子；Claude Code 的 `async function* query()`。

```python
async def run(state, input, cfg) -> AsyncIterator[Event]:
    yield AgentStart()
    pending = [input]
    while True:
        msgs = await cfg.prepare_request(state, pending)  # 钩子：上下文引擎在这里组装
        async for ev in cfg.gateway.stream(msgs, tools=state.tools, signal=state.abort):
            yield ev  # 文本增量、推理增量、工具调用增量
        calls = state.last_assistant.tool_calls
        if calls:
            async for ev in execute_tools(calls, cfg):  # 默认并行；标了 sequential 的工具串行
                yield ev  # before_tool 可拦截，after_tool 可改写
        decision = await cfg.finish_turn(state)  # 钩子：结束 / 继续 / 交给状态机
        if steer := state.queues.pop_steer():  # 用户中途插话
            pending = [steer]
            continue
        if calls and decision != "end":
            pending = []
            continue
        if follow := state.queues.pop_follow_up():
            pending = [follow]
            continue
        break
    yield AgentEnd()
```

| 机制 | 做法 |
|---|---|
| 事件 | `agent_start/end`、`turn_start/end`、`message_start/update/end`、`tool_start/update/end`、`state_transition`、`compaction`，前端和 trace 都订阅同一个事件流 |
| 工具 | Pydantic 定义参数，自动生成 JSON Schema；参数校验失败把错误回给模型；工具抛异常即 `is_error`；可返回 `terminate` 提示本批结束 |
| 并行工具 | 预检串行、执行并发、结果按模型给出的顺序写回（保证可重放） |
| 中途插话 | `steer` 在当前工具批次完成后注入；`follow_up` 在本轮自然结束后注入；`collect` 合并短时间内的多条消息 |
| 取消 | 每个请求带 `asyncio` 取消令牌，向下传到模型网关和工具；取消后记录 `aborted` 事件，可从中断处继续 |
| 预算 | 单轮最大工具调用次数、最大 token、最大成本；超出时结束并告知用户 |
| 死循环保护 | 连续 3 次相同工具调用且参数相同，强制结束并记录 |

## 2. 上下文引擎（`kaopu_agent.context`）

参考：Claude Code 的分层系统提示和四级压缩；Codex 的“用户原话按最新优先保留”；OpenClaw 的可插拔 ContextEngine；Hermes 的会话内冻结快照。

### 2.1 分层组装

顺序固定，稳定的放前面以命中 prompt cache：

| 层 | 内容 | 缓存 | 预算（占可用窗口） | 超出时 |
|---|---|---|---|---|
| L0 系统策略 | 角色、来源标签规则、材料围栏规则、输出格式 | 全局稳定 | 固定约 1.5k token | 不裁 |
| L1 工具声明 | 当前状态可用的工具（按状态裁剪，不是全部工具） | 按状态稳定 | 约 1–2k | 不裁 |
| L2 课程元信息 | 课程名、章节目录、考试日期、模式 | 会话内稳定 | 约 0.5k | 目录只保留当前章附近 |
| L3 学习者快照 | 画像块 + 当前章掌握度 + 未解决错因 Top N | 会话开始时冻结 | 约 0.8k | 减少 N |
| L4 教学指令 | 状态机给出的本轮任务（例如“讲第 3 段，讲完提一个检查问题”）+ 按需加载的教学策略 | 每轮变化 | 约 0.5k | 不裁 |
| L5 证据 | 当前段原文 + 检索证据，每块带 `E` 编号 | 每轮变化 | 25–40% | 按相关度截断 |
| L6 会话摘要 | 早期对话的结构化摘要 | 压缩时变化 | 约 1k | 再压缩 |
| L7 近期对话 | 最近几轮原文 | 每轮变化 | 剩余部分 | 触发压缩 |

每层有独立 token 计数（先用 tiktoken 估算，再用厂商返回的 usage 校正）。前端的“检查器”面板能看到每层用了多少 token，这也是演示时的亮点。

### 2.2 小窗口模型档位

延续 Skill 的 small/standard/large。按模型能力表自动选择：

| 档位 | 适用 | 每段原文 | 每次出题 | L5 证据块 |
|---|---|---|---|---|
| small | 上下文 ≤ 32k 或本地 4B–8B 模型 | 中文 1800 字 | 1 | 3 |
| standard | 32k–200k | 3000 字 | 3 | 6 |
| large | 200k 以上 | 8000 字 | 5 | 12 |

### 2.3 压缩

| 级别 | 触发 | 做法 | 参考 |
|---|---|---|---|
| 1 证据回收 | 每轮 | 已讲完段落的 L5 证据换成占位符“E123: lec2 p.3（已省略，可用工具重新读取）” | Claude Code microcompact |
| 2 工具结果截断 | 单条结果超过上限 | 保留头尾，中间换成句柄，模型可按需读取 | |
| 3 滚动摘要 | 窗口占用达到“有效窗口 − 预留输出”，预留部分不超过窗口的 1/3 | 由便宜模型按固定模板写摘要：当前位置、未解决的问题、本次错题 id、学生原话中的关键困惑、已承诺的下一步。学生在当前题的作答原文不进摘要，原样保留 | Codex、cc-haha |
| 4 溢出兜底 | 厂商返回上下文超长 | 立即执行级别 3，重试一次 | Claude Code reactive compact |

保护：压缩连续失败 3 次就停止压缩，改为硬截断并告警；压缩后 3 轮内又回到阈值，说明在反复回填，停止压缩并提示开新会话。

**为什么学习场景的压缩可以做得很稳**：学习进度、错题、掌握度本来就在数据库里，摘要丢了信息也不会丢进度。这是“结构化状态 + 对话摘要”双轨的好处，可以在面试里重点讲。

## 3. 记忆（`kaopu_agent.memory` + `kaopu.learner`）

参考：Letta 的分层记忆、Mem0 v3 的只追加写入、Hermes 的有上限画像、Claude Code 的记忆索引。

| 类型 | 存什么 | 存储 | 写入 | 读取 |
|---|---|---|---|---|
| 工作记忆 | 当前上下文 | 内存 | 上下文引擎 | 每轮组装 |
| 情景记忆 | 每次会话摘要、关键事件（“第 3 章条件概率讲了两遍才懂”） | Event 表 + 摘要表 + 全文索引 | 会话结束后由 Curator 子 Agent 后台提炼 | 新会话开始时取最近 N 条；学生问“上次讲到哪”时检索 |
| 语义记忆 | 掌握度、FSRS 卡片、错因、笔记 | 结构化表 | 只由判分结果和明确的工具调用写入，模型不能随意改 | L3 快照、Planner |
| 程序记忆 | 教学策略（怎么讲证明题、怎么讲图题、提示阶梯）+ 这个学生的偏好（例子先行还是公式先行） | `skills/*.md` + `ProfileBlock` | 策略由开发者维护；偏好由 Curator 根据反馈提议，用户确认 | 状态机按需加载对应策略 |

几条硬规则：

1. **关于学生的事实必须结构化**。“学生掌握了贝叶斯公式”不能是模型写的一句话，只能来自答对材料题后的 BKT 更新。这避免了记忆层面的幻觉。
2. **画像块有字数上限**（例如 1200 字），写满时返回错误，由 Curator 合并精简。用户可以在设置页直接查看和修改。
3. **只追加**：Attempt、ReviewLog、Event 不覆盖不删除，掌握度是从它们重新计算出来的，可以随时重算。
4. **会话内冻结**：L3 快照在会话开始时生成，会话中途更新只写数据库，不改上下文，以保住缓存。

## 4. 多 Agent 协作（`kaopu_agent.subagent` + `kaopu.agents`）

参考：Claude Code 的 Task 子 Agent 和只读 verifier；Anthropic 关于“何时用多 Agent”的讨论。

**只在两种情况下拆子 Agent**：需要上下文隔离来保证正确性，或者需要并行来降低延迟。其他情况一个 Agent 加工具就够了，多拆只会增加成本和延迟。

| 角色 | 为什么独立 | 模型档 | 上下文 | 工具 | 输出 |
|---|---|---|---|---|---|
| Tutor（主 Agent） | 和学生对话 | 强 | 完整（第 2 节） | 检索、取段落、看图、记笔记、出题请求 | 流式文本 |
| Examiner | 选题逻辑与讲解解耦 | 规则为主 | 无需 LLM，难题挑选可选 LLM | 题库查询 | 题目 id 列表 |
| Grader | **必须看不到讲解过程**，避免和 Tutor 互相迁就 | 便宜 | 题目 + 参考答案 + 评分要点 + 学生答案 | 无 | `GradeResult` 结构体 |
| Verifier | 校验必须独立于生成 | 便宜 | 句子 + 引用的证据块 | 无 | 每句 `supported/partial/unsupported` |
| Planner | 计划是优化问题 | 规则为主，LLM 写说明 | 掌握度、到期卡、考试日期 | 无 | 今日任务 |
| Curator | 后台整理记忆，不占用对话 | 便宜 | 会话事件 | 记忆写入（受限） | 情景摘要、画像修改提议 |
| Extractor | 导入时批量抽知识点 | 便宜 | 单章原文 | 无 | `KnowledgePoint[]`，每个带证据 id |

实现要点：

- 子 Agent 返回 **Pydantic 结构体**，而不是一段对话记录。主 Agent 只看结构化结果，避免把子 Agent 的长输出塞进主上下文。
- 子 Agent 复用 L0 前缀以命中缓存（Claude Code 的 `model: inherit` 思路）。
- 后台子 Agent（Curator、预生成复习卡）完成后通过事件通知，不阻塞对话。
- 每个子 Agent 有独立的预算和超时；超时降级为规则结果（例如 Grader 超时就展示参考答案让学生自评）。

## 5. 并发（`kaopu.server` + `kaopu_llm.gateway`）

| 层级 | 问题 | 做法 | 参考 |
|---|---|---|---|
| 会话内 | 同一会话同时来两条消息会把状态写乱 | 每个会话一个 lane（asyncio 队列 + 单消费者），默认串行；生成中来新消息按 steer / follow_up / collect 处理 | OpenClaw Lane Queue |
| 会话间 | 多人、多课程同时使用 | 会话之间完全并行；会话 actor 空闲超时后回收 | |
| 同一用户多设备 | 手机和电脑同时答题 | 学习者状态行带版本号，乐观锁冲突时重读重算；写作答记录带幂等键，重试不会重复记分 | |
| 模型调用 | 厂商限流、偶发失败、长尾延迟 | 每厂商令牌桶（RPM + TPM）、全局并发上限、指数退避加抖动、熔断器（连续失败后切到降级链的下一个模型）、可选对冲请求 | |
| 子 Agent 并行 | 讲解时同时校验、预取、预生成 | `asyncio.TaskGroup`，任一失败不影响主回复 | |
| 资料导入 | 1000 页 PDF 解析和裁图是 CPU 密集 | 进程池（pdfium 非线程安全），按文件和页分片；LLM 抽取任务受网关限流 | |
| 任务持久化 | 进程崩溃后导入要能继续 | 任务表 + 租约，过期租约的任务被重新领取；任务幂等 | |
| 背压 | 用户上传过多文件或请求过快 | 有界队列，满了返回 429 并告知预计等待时间 | |

## 6. 持久化与回放（`kaopu_agent.session`）

- **事件溯源**：会话里发生的一切都是 `Event`，按 `seq` 只追加。当前状态是事件的投影。
- **分叉**：从任意事件分叉一个新会话（“换一种讲法再讲一遍”），新会话 `parent_id + fork_at_seq` 指向原处，参考 pi 的树形会话。
- **崩溃恢复**：未完成的轮次在重启后可以继续或标记为中断。
- **确定性回放**：记录每次模型请求的输入哈希和输出，测试时可以用录制结果回放，这也是后期 benchmark 的基础。

## 7. 反幻觉：引用由系统生成（`kaopu.knowledge` + Verifier）

这是项目最核心的卖点，设计成“结构上就不可能编页码”。

1. **证据编号**：L5 里每块证据带短编号 `E1…En`，编号到 `(文件, 页, 字符区间, bbox)` 的映射只存在服务端。
2. **模型只写编号**：系统提示要求引用写成 `[[E3]]`。模型写不出页码，因为它根本不知道编号对应哪一页之外的信息，渲染时由服务端替换。写了不存在的编号会被直接剔除并记录。
3. **逐句校验**：回答按句切分。带 `[[E]]` 的句子交给 Verifier 判断证据是否支撑；不支撑的句子降级为 🟡，或在严格模式下重写。前端先流式显示，校验结果随后以标记更新（“已核对”）。
4. **拒答判定**：检索最高分低于阈值，且 Verifier 判断“证据不足以回答”时，回复“资料里没有讲到”，可选附一段标 🟡 的补充。
5. **题目只来自题库**：Tutor 没有“出新题”的工具。资料里没有题的章节，可以由专门工具生成练习题，强制标 ⚠️，不计入 `verified`。
6. **题干缺失**：只有教材题号时，沿用 Skill 的做法，只复述参考答案开头的已知条件并标 🟡。

## 8. 安全

| 威胁 | 做法 |
|---|---|
| 课件里的注入指令 | 移植 `guard.py`：材料一律放进带内容哈希 id 的围栏；28 条中英文规则检测；命中时在 UI 上提示学生 |
| 模型被诱导调用危险工具 | Agent 没有 shell、没有任意文件写、没有联网工具；工具按状态白名单开放；`before_tool` 统一做权限检查 |
| 路径穿越 | 所有文件访问限制在课程目录和工作区内（沿用 Skill 的测试） |
| 多租户越权 | 所有查询强制带 `tenant_id`，在数据访问层统一注入，不依赖调用方记得加 |
| 密钥泄露 | API Key 存系统钥匙串（keyring）或环境变量，日志和 trace 自动脱敏 |
| 资源滥用 | 每用户每天的 token 和成本上限；上传文件大小和数量上限 |

## 9. 模型网关（`kaopu_llm`）

- **三种协议覆盖绝大多数厂商**：OpenAI 兼容（含 DeepSeek、通义、GLM、Kimi、MiniMax、硅基流动、OpenRouter、Ollama、LM Studio、vLLM、llama.cpp）、Anthropic 原生、Gemini 原生。
- **能力表**：每个模型记录上下文长度、最大输出、是否支持工具调用、视觉、推理模式、prompt cache、价格。上层按能力做决策（例如不支持工具调用的本地模型改用 JSON 模式）。
- **按角色路由**：`tutor`、`grader`、`verifier`、`extractor`、`summarizer`、`embedding` 各自配置模型和降级链。
- **统一事件**：不同厂商的流式输出统一成同一套事件；推理内容单独一个通道，默认不展示给学生。
- **用量与成本**：每次调用记录 token、缓存命中、成本，按会话、用户、角色汇总。

## 10. 可观测性

- 遵循 OpenTelemetry GenAI 语义约定，span 层级：会话 → 轮次 → 模型调用 / 工具调用 / 检索 / 校验。
- 本地模式自带 trace 查看器（Web App 的“检查器”面板）：每轮的上下文分层、token 用量、检索命中、校验结果、耗时、成本。
- 服务器模式可导出到 Jaeger、Langfuse 等。
- 指标：首 token 延迟 P50/P95、每轮成本、缓存命中率、校验降级率、拒答率、工具错误率。

## 11. 测试策略

- **假模型**：`FakeProvider` 按脚本返回流式事件和工具调用，循环、压缩、并发逻辑都用它做确定性测试。
- **录制回放**：真实模型的请求和响应录制成固定文件，CI 里回放。
- **移植 Skill 的 43 个测试**作为资料引擎回归基线。
- **并发测试**：同一会话并发投递消息，断言事件顺序和状态一致；模拟厂商 429 和超时，断言重试和降级行为。
- **安全测试**：注入样例集、路径穿越、跨租户访问。
